# Poker 敏捷估点工具设计

## 1. 设计目标

构建一个面向敏捷团队的多人实时 Poker 估点工具。用户无需注册账号即可创建或加入项目房间，在同一轮中选择 Fibonacci 牌、隐藏投票、由主持人揭牌并记录最终估点。

首版目标：

- 支持多个相互隔离的项目房间。
- 每个房间最多 100 个在线成员。
- 支持主持人、投票者、观察者三种角色。
- 支持连续多轮估点，并保留最近 20 轮结果。
- 以全球访问速度和免费部署为优先。
- 采用深色绒布、金色强调、复古扑克牌和优雅动效的 Velvet Table 视觉方向。

不在首版范围内：

- 账号注册、OAuth 和用户资料。
- 聊天、音效、报表导出和复杂项目仪表盘。
- 任意自定义牌组；首版只提供 Fibonacci。
- 平均值或中位数展示。
- 免费层之外的高可用 SLA 承诺。

## 2. 用户与房间模型

### 2.1 身份

用户输入昵称即可进入房间。后台使用匿名身份建立安全连接，但不向用户暴露账号概念。浏览器保存临时恢复令牌，使刷新或短暂断线后可以恢复成员身份。

昵称只用于展示，不承担权限职责。

### 2.2 角色

- **主持人**：创建房间，开始/结束/重置轮次，揭牌，录入最终估点，转交主持权，修改成员角色。
- **投票者**：选择或修改 Fibonacci 牌，参与当前轮投票。
- **观察者**：查看房间状态和结果，但不能投票。

创建者默认成为主持人。主持人断线超过宽限期后，主持权自动交给最早加入的投票者；主持人也可以主动转交。

### 2.3 房间

一个项目对应一个独立房间，通过高熵随机邀请码和分享链接加入。房间最多容纳 100 个在线成员；达到上限后拒绝新成员。

房间保存：

- 项目名和创建时间。
- 当前成员及角色。
- 当前轮次和状态。
- Fibonacci 牌组。
- 最近 20 轮的投票分布、最终估点和时间。

首页在浏览器本地保存最近访问房间，首版不提供云端项目列表。

## 3. 技术架构

### 3.1 前端

- React + Vite + TypeScript。
- Cloudflare Pages 部署静态资源并使用全球 CDN。
- 使用自定义 CSS 实现 Velvet Table 视觉，不引入大型 UI 框架。
- 使用 `transform` 和 `opacity` 实现主要动画，支持 `prefers-reduced-motion`。

### 3.2 实时与持久化

- Supabase Postgres 保存房间、成员、轮次、投票和历史。
- Supabase Realtime 推送房间成员、轮次和投票状态变化。
- 客户端只订阅当前房间频道，不让成员互相建立连接。
- 受控数据库函数或边缘接口负责所有改变状态的操作，客户端不能直接写入任意字段。

### 3.3 建议数据实体

逻辑实体包括：

- `rooms`：房间标识、邀请码、项目名、当前轮次、主持人、在线上限和过期信息。
- `room_members`：匿名成员、昵称、角色、加入时间、最后心跳和在线状态。
- `rounds`：房间、轮次编号、状态、开始/揭牌/归档时间和最终估点。
- `votes`：轮次、成员、牌值、提交时间；同一成员同一轮只能有一个当前投票。
- `round_results`：轮次的牌面分布和最终估点。

数据库启用 RLS。邀请码只用于找到房间，具体操作仍需通过匿名身份、成员关系、角色和当前状态校验。

## 4. 状态与数据流

### 4.1 轮次状态机

```text
voting -> revealed -> archived
   ^                    |
   +------ next round --+
```

- `voting`：投票者可提交或修改投票，牌值对其他成员隐藏。
- `revealed`：主持人揭牌后冻结投票，展示所有牌和牌面分布。
- `archived`：主持人录入最终估点后保存结果；随后可创建下一轮。

Reveal、归档和重置操作必须校验当前状态，并设计为幂等，防止重复点击和过期客户端覆盖。

### 4.2 投票流程

1. 主持人开始一轮。
2. 投票者选择 Fibonacci 牌，可在揭牌前修改。
3. 客户端显示本人已提交，但不泄露牌值。
4. 主持人点击 Reveal。
5. 服务端冻结投票；客户端展示每位成员的牌和牌面分布。
6. 主持人输入最终估点并归档。
7. 主持人开始下一轮，或结束项目。

结果区只显示牌面分布和主持人录入的最终估点，不显示平均值或中位数。

### 4.3 断线与恢复

客户端显示连接中、重连中和已连接状态。重连后先获取服务端快照，再重新订阅 Realtime，避免只依赖丢失的事件。

投票只有获得服务端确认后才标记为已提交。主持人离开后按宽限期和加入顺序自动转交主持权。成员恢复失败时明确提示重新加入，而不是静默创建新身份。

## 5. 界面与动效

### 5.1 首页

深色绒布背景和中央牌堆作为品牌入口，提供“创建项目”和“加入项目”两个主操作。创建成功后立即展示邀请码和分享链接。

### 5.2 房间桌面

- 顶部：项目名、当前轮次、在线人数和主持人控制。
- 中央：轮次状态、故事卡或当前估点上下文。
- 底部：Fibonacci 牌列。
- 右侧：按主持人、投票者、观察者分组的成员列表。
- 移动端：成员列表收纳为顶部抽屉，牌列横向滚动。

### 5.3 动效

- 未选牌轻微浮动。
- 选中牌抬升并出现细金色边缘。
- Reveal 时牌面依次翻开。
- 结果分布柱状条从底部生长。
- 新轮次通过洗牌过渡切换，避免整页闪烁。

所有动效提供减少动态效果模式。牌面、按钮和成员状态有键盘焦点、文本标签和足够对比度。

## 6. 错误处理与安全边界

- 房间满员：拒绝加入并显示当前人数与上限。
- 房间不存在或已过期：显示可恢复的明确说明。
- 权限不足：操作按钮隐藏或禁用，同时服务端再次拒绝非法请求。
- 状态冲突：以服务端版本号和当前状态为准，刷新快照后提示用户重试。
- Realtime 断开：保留本地界面状态但不伪造成功，恢复后重新同步。
- 匿名身份失效：要求用户重新输入昵称加入，并明确说明原成员身份无法恢复。
- 牌值、角色和轮次转换由服务端函数校验，避免客户端篡改。

## 7. 验证计划

### 单元测试

- 轮次状态机转换。
- 角色权限矩阵。
- 牌面分布计算。
- 主持人自动转交规则。
- 重连和快照合并逻辑。

### 集成测试

- 创建、加入和满员限制。
- 投票提交、修改、冻结和 Reveal。
- 归档最终估点、开始下一轮和最近 20 轮限制。
- 主持人转交与断线恢复。
- RLS 和服务端函数对非法成员/角色/状态的拒绝。

### 浏览器测试

- 首页创建/加入流程。
- 桌面与移动布局。
- 牌面选择、Reveal 和分布动画。
- 观察者不可投票。
- 减少动态效果模式。
- 断线提示与重连后的状态恢复。

### 性能验证

上线前使用 100 个模拟成员验证单房间的加入、投票、Reveal 和重置同步。重点观察 Realtime 连接数、状态传播延迟、数据库写入错误和客户端渲染性能。

## 8. 部署与限制说明

前端发布到 Cloudflare Pages，Supabase 提供数据库、匿名身份和 Realtime。免费层用于首版和小规模团队验证；README 必须说明免费层可能存在休眠、容量、连接数和流量限制，并提供升级或替换实时服务的边界。

`.superpowers/` 仅存放设计陪伴产生的临时预览，不属于产品源代码，应加入 `.gitignore`。
